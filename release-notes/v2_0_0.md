# v2.0.0

- **`gth exec`, `gth batch`, `gth eval` and `gth workflow` run Gaunt Sloth without a session.**
  `exec` runs a markdown prompt-executable once and pipe-clean, `batch` fans one across a matrix of
  inputs and models, `eval` grades agent output against suites with judges and metric gates, and
  `workflow` drives several agent calls from a local JavaScript script.
- **`gth config`, `gth models`, `gth history` and `gth insights` are new local surfaces, taking the
  CLI from eight commands in 1.x to sixteen with all eight still there.** `config` prints and
  validates the resolved configuration, `models` lists each provider's models with cost and
  context-window metadata, and `history` and `insights` search and summarise recorded sessions.
- **`gth chat` and `gth code` open a full-screen terminal interface** — scrollable transcript,
  collapsible reasoning, and a multi-line editor with bracketed paste and slash-command completion.
  Mouse reporting is on by default, so hold Shift while dragging to select text as your terminal
  normally would, or turn it off with `/mouse off`; `--no-tui` keeps the plain readline surface.
- **The agent can now propose arbitrary shell commands, which it could not in 1.x, and one ordered
  ladder of five modes gates them** — `manual`, `write`, `assisted` (the default), `auto`, `bypass`.
  A safety rater classifies each proposed command at `assisted` and `auto` only, while a
  deterministic floor refuses the worst of them under every mode, before any model is consulted.
- **Sessions are recorded to `~/.gsloth/history.db` by default and can be resumed** — `--resume
  <id>` or `/resume` picks a conversation up where it left off, and `/compact` folds a long one
  down, as the session itself now does once when a turn overflows the model's context window instead
  of ending the turn. Nothing leaves the machine, but a `chat` or `code` session stores tool results
  verbatim, file contents and command output included and unredacted; `history.enabled: false` is
  the off switch.
- **`gth review` can find its own requirements, as `gth pr` already could in 1.x.** Turned on with
  `commands.review.discovery`, it takes the issue from the branch name and the branch's pull
  request, fetching a Jira key directly or handing the evidence to a discovery agent with the tools
  you allow, such as a Jira MCP server. A new `git` content source runs the diff itself, and with
  `contentSourceConfig.git.mergeBase` it reviews a branch the way its pull request will show it,
  uncommitted edits included — see
  [the worked example](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.0/docs/guides/review-code-and-prs.md#review-a-branch-against-its-jira-issue-locally-and-in-the-pull-request).
- **Configuration is validated strictly against a single schema.** `gth config validate` checks a
  config without building an LLM or running anything, a `.gsloth.config.ts` exporting `configure()`
  is supported alongside the JSON and JavaScript forms, and the project config is now found by
  walking up from the directory you run in.

## Breaking Changes

Before upgrading a 1.x config, read [docs/MIGRATION.md](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.0.0/docs/MIGRATION.md) and check the result with `gth config validate`.

- **The package is renamed: 2.0 installs as `gaunt-sloth`, where the 1.x package is
  `gaunt-sloth-assistant`.** Run `npm rm -g gaunt-sloth-assistant` before `npm i -g gaunt-sloth` —
  installing over the old package can abort the entire install over a bin name it already owns,
  after which `gth --version` goes on quietly reporting the 1.x version.
- **Deprecated config shapes are now hard errors, with no back-compat coercion:** a boolean
  `rating`, a top-level command key, a `*Provider*` name, per-command `devTools`, the flat prompt
  keys and a `video` or `binary` entry in `binaryFormats` each abort the run, and a script passing
  the removed `--content-provider` or `--requirements-provider` flags errors out. Fix them before
  you upgrade; most messages name the replacement, though a boolean `rating` reports only a type
  error.
- **Three defaults changed without raising any error.** `output.header` is now `compact`, so a text
  run opens with one attribution line instead of the preamble; `writeOutputToFile` is now `false`,
  so the `gth_<timestamp>_<COMMAND>.md` report files are no longer written; and session history is
  on — set each one back explicitly if you relied on it.
- **`gth api ag-ui` and the standalone `gaunt-sloth-api` now bind `127.0.0.1` rather than every
  network interface, because the endpoint carries no authentication.** Pass `--host 0.0.0.0` to
  serve another machine, `::` if that client is IPv6, or `::1` for a local client that resolves
  `localhost` to IPv6 — one listen binds one address, so `::1` then refuses anything dialling
  `127.0.0.1`; `commands.api.host` sets the same from config.
- **`gth review` and `gth pr` now exit non-zero when the run fails inside the agent, where 1.x
  exited 0.** A provider error, or anything else that stops the agent before a verdict, used to
  print the failure and still report success — so a CI job keyed on the exit code went green over a
  review that never happened. This is deliberately not gated on `errorOnReviewFail`, which governs
  what to do with a verdict a review actually reached.
- **Embedders must import from the scoped packages.** The 1.x `gaunt-sloth-assistant` package
  exported its modules; `gaunt-sloth` exports only its own `package.json`, so import from
  `@gaunt-sloth/core`, `@gaunt-sloth/agent`, `@gaunt-sloth/review` or `@gaunt-sloth/batch` instead.
