# v2.1.6

- **Breaking:** `gth eval` rejects a suite that contains a key the suite format does not define, so a misspelt operator such as `contain:` can no longer leave a weaker check in its place. A suite with such a key now fails to load with exit `2` until the key is corrected or removed. The error names each key, where it is and the keys accepted there, and prints at most 10 issues.
- YAML `<<` merge keys in a suite are now expanded, so an assertion bundle shared through an anchor is applied to every case that merges it. Before, the merged assertions were silently dropped, so such a case may now fail where it passed. The anchor must sit inside the suite's own structure; a top-level helper key such as `x-common:` is rejected as an unknown key. See [Suite file](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.1.6/docs/COMMANDS.md#suite-file).
- A suite and each case accept a `description:`. It is documentation only.
- `tool_call_json_path` entries accept `matches` (a regular expression tested against the value), `present: false` (the argument must not be sent) and `all_calls: true` (every call to the tool must satisfy the entry, not just one).
- With `evalToolCallArgs` on, a tool call the model wrote as plain text (such as `[tool:lookup_customer]{"query":"acme"}`) is now recorded in `toolCalls` on a streamed run, so `tool_call_json_path` can check it. Before, the tool ran but the case failed with "no call to a matching tool".
