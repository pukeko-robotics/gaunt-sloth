# v2.4.1

- Installing Gaunt Sloth no longer brings in zod 3 through the AG-UI encoder, so `npm audit` stops reporting the zod advisory GHSA-mrhx-c7xc-m3w5 against it.
- `gth eval` can grade a command-line agent such as Claude Code: a `command` target starts it once per case and grades its tool calls and results from the transcript it prints. Running such a suite runs its command. See [The command target](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#the-command-target).
- A `command` eval case can run in its own fresh workspace: a copy of a fixture directory, prepared by `setup` steps and given its own `env`, and removed when the case ends, so cases that edit files can run in parallel. `--keep-workspaces` keeps them for inspection. See [Workspaces](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#workspaces).
- A `command` eval case can check what the agent left in its workspace: `file_contains` for a file's text, `must_not_exist` for files that should not be there, and `after` for commands such as `git status` whose output or exit code must match. `after` commands run without asking, like `setup`. See [Workspace assertions](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#workspace-assertions).
- A `command` eval workspace can start the agent in a subdirectory with `cwd`, remove an inherited variable with `env: { NAME: null }`, and let a case change only some keys of the default workspace with `inherit: true`. See [Workspaces](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#workspaces).
- An eval case can run several times and pass at a set rate: `repeat` and `pass_rate`, in `defaults` or on a case, for every target. The report shows each repeated case's rate and every run's outcome, a run that could not run at all fails the case as a harness error, and `--compare-to` lists a case whose rate fell as flaky and one that fell to zero as broke. Each run costs a full agent run. See [Repeated cases](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#repeated-cases).
- An eval case can check that no tool call sent a value: `none: true` on a `tool_call_json_path` entry fails the case if any call to the tool matches, and passes when the tool was never called. See [Tool-call argument assertions](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#tool-call-argument-assertions).
- `gth eval --only <pattern>` runs just the cases whose id matches, exactly or with `*`, so you can work on one case without paying for the whole suite; a pattern that matches nothing exits 2 before anything runs. `--keep-transcripts` keeps what a `command` agent printed in each run, failed runs included, beside the case's results. See [Running some of the cases](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#running-some-of-the-cases).
- A `command` eval case can be graded on a run that stopped at a limit you set, such as Claude Code's `--max-turns`, instead of failing as a harness error: list the ending in `grade_when`, as in `grade_when: [error_max_turns]`, on the target or on a case. Such a run is marked `ended on error_max_turns` in the report and in its JSON. Without the key nothing changes. See [Grading a run that hit a limit](https://github.com/pukeko-robotics/gaunt-sloth/blob/v2.4.1/docs/COMMANDS.md#grading-a-run-that-hit-a-limit).
- Behaviour change: refusing one tool call no longer cancels the other calls the agent made in the same step. The calls that need no approval, or that you approved, now run, and only the one you refused is skipped.
