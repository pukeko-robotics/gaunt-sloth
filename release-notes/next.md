# v2.1.6

- With `evalToolCallArgs` on, a tool call the model wrote as plain text (such as `[tool:lookup_customer]{"query":"acme"}`) is now recorded in `toolCalls` on a streamed run, so `tool_call_json_path` can check it. Before, the tool ran but the case failed with "no call to a matching tool".
- `tool_call_json_path` entries accept `matches` (a regular expression tested against the value), `present: false` (the argument must not be sent) and `all_calls: true` (every call to the tool must satisfy the entry, not just one).
- `gth eval` rejects a suite that contains a key the suite format does not define, naming the key and where it is and listing the keys that object accepts. A misspelt operator such as `contain:` used to be dropped, leaving a weaker check. A suite that carried an unused key now fails to load (exit `2`) until the key is removed. The error lists each set of accepted keys once and prints at most 10 issues. A suite and each case accept a `description:`, and YAML `<<` merge keys are expanded before the check.
